### WFO Philosophy (answered during session):

Traditional WFO: Training period = the period where you SELECT parameters. Testing period = where you EVALUATE with
those fixed parameters. The training IS the grid search — you're finding the best params on the IS (in-sample) window.

In our case: The grid search IS the training. We test every combo on the full period, pick the best sharpe. WFO then
tests whether that "best" combo generalizes to unseen periods. Specifically:

• IS (in-sample) fold: Run the grid search on a TRAINING window → find best params
• OOS (out-of-sample) fold: Take those best params, run on a TEST window → measure performance
• If IS sharpe is high but OOS sharpe is negative → overfit
• If both are positive → robust

Why not "just test different periods": Random period testing doesn't control for look-ahead bias. WFO enforces a strict
temporal separation: you NEVER see the future data when selecting params. Without this, you can accidentally overfit to
the entire dataset.

The user's valid point: If we're going to use the same grid params anyway (not re-optimizing per fold), then WFO is
testing whether the SINGLE best combo from the full-period grid holds up across time. This IS meaningful — it tests
temporal stability. But the "training" is the full grid search, and the OOS is each fold's unseen window.

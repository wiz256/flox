## Speed: What changed?

 Before                                                     │ After
────────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────────
  OhlcvReplaySource  →  onSymbolTrade                       │  runBars(BarEvents)  →  onSymbolBar
 ~60s per symbol                                            │ ~3s per symbol
 14+ min for 1 symbol                                       │ 2m10s for all 40

Two things helped:

1.  runBars  dispatches  onSymbolBar  — FLOX passes full OHLCV bars directly, no synthetic trade generation overhead
(~100x faster path internally)
2.  emitClosePosition()  — our first  runBars  attempt used  emitMarketSell  which OPENS shorts instead of closing longs
producing zero trades.  emitClosePosition()  is the correct reduce-only exit

## What's wrong with the current implementation

### 1. Position Sizing — hardcoded  0.01  quantity

Our code:  qty_(Quantity::fromDouble(0.01))  — this is 0.01 units regardless of price. BTC at $100K = $1,000 notional.
DOGE at $0.10 = $0.001 notional. Completely broken for cross-coin comparison.

The  claude-glm  reference implementation already solves this with  qtyFromNotional(price)  and 3 sizing modes. FLOX has
no native position sizing — it's purely strategy-level ( Quantity::fromDouble(notional / price) ).

### 2. Walk-forward is oversimplified

Current: 5 folds, skips training entirely, only tests OOS segments. Uses  bars.size() / 10  per fold with no concept of
months.

### 3. White's Reality Check tests the underlying, not the strategy

It bootstraps buy-and-hold returns of the coin itself — not the strategy's trade returns. This is wrong.

### 4. Plateau detection only checks p1 dimension

Only looks at ±2 on  signal_p1 , ignores p2/p3 and exit params.
